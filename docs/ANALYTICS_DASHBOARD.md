## 実処理MSPTの方式（受け入れ済み、既存サーバーへ未配備）

以下の古い「処理MSPTは常に未計測」という設計上の制限は、新方式の実装では撤廃しています。
ただし、**稼働中18767番のプロセス／既存DLLは更新していません**。その画面に新しい実測値が
自動的に現れるわけではありません。実BDSの新方式データがない場合は今までどおり未計測です。
最新の候補DLL、実BDS検証の成否と制限は `STATUS.md` の最上部を参照してください。

計測方式は [Pierの固定ソース](https://github.com/Maskviva/Pier/blob/f841e43a251444b326557e4e225574d0f65663f3/packages/pier-hooks/src/engine/TickStats.cpp)
を参考に、公式26.60の `Level::$tick` をHighest／Lowest優先度で挟みます。
Highest側の `origin()` 前後をsteady_clockで測った処理経過時間を、Lowest側で確認した
**本当に実行されたtick数**で割ります。BDSの外部スケジューラによるtick間のsleepや
`mTickDeltaTime` をMSPTには使いません。CPU使用率／CPU命令の実行時間ではなく、
Level処理と内側のMod処理・待機も含む「処理範囲の経過時間」です。

- 平均MSPT = 窓内処理ns合計 ÷ 実tick数 ÷ 1,000,000。
- 実効TPS = 実tick数 ÷ 窓内経過秒。新方式はwarpの60TPS等を20へ丸めません。
- 20TPS／処理2ms／外部sleep48msならMSPTは2msであり50msではありません。
- freeze中も外側フレームが観測でき、内側tickが0ならTPSは0、MSPTは未定義（未計測）。
- 表示の最大値はLowest側の1tick処理最大です。平均の外側範囲と違うため、
  「最内周1tick最大」と説明に表示します。p95は未実装でnull、仮の値は作りません。

5秒以上の固定メモリ窓でのみキューへ渡し、SQLiteは単一workerが書きます。
保存は既存v4の `events` に、cause=`ll26.60.busytick.v1`、amount=実tick数、
details_jsonへ `clock=steady`, `hook=Level::$tick/Highest+Lowest`, `wall_ns`, `busy_ns`,
`max_inner_ns`, `frames`, `sampled_peak_online` を保存します。旧整数MSPT列には混ぜません。
開始・終了・無効化の別通知で、前回起動の値が復活しないようにします。
再帰／別Level／別スレッド／例外／不正時刻は計測を無効化します。
20秒超の古い値、不正形式、終了後は現在MSPT・TPS・人数をnullにします。

新コードの `/api/v1/analytics` と既存の日本語MSPTカードはこの形式を表示できます。

Python 3.13.15 / 標準 SQLite 3.50.4 で検証済みです。追加パッケージやダウンロードは不要です。

```powershell

```

2. 新プロセスの **http://127.0.0.1:18768/**（基礎4分類）または **http://127.0.0.1:18768/actions**（追加行動）で、
   その新しい閲覧トークンを貼り付けて「接続」を押します。18767番のトークンは流用しません。
3. 日別／月別／全期間、JSTの日付、ランキング指標、プレイヤーを選びます。

   既存18767番を止めないでください。

トークンは暗号学的乱数256 bit相当で起動ごとに新規作成、8時間で失効します。

## 集計の定義

- 保存時刻は変更せずUTC epochミリ秒のまま。表示と期間選択はJST（UTC+09:00）です。
  日はJST 00:00以上〜翌00:00未満、月も月初〜翌月初の半開区間。未来の期間は拒否します。
- 確定時間は `sessions` の終了時刻・durationが整合する行だけを利用します。
  JST区間で切り取り、同一プレイヤーの重複・包含・連鎖重複セッションは**和集合**にして二重加算しません。
  期間外に始まったセッションでも期間に重なる確定時間は算入します。
- セッション数は**期間内に開始した保存セッション数**です。日跨ぎの時間とは対象区間が異なります。
  異なるIDの重複開始行は記録として数えますが、プレイ時間は重複加算しません。
- 終了していないセッション、負の時間、duration不整合、未来の終了時刻は確定時間から除外します。
  未完了／不正の件数は全履歴の診断値です。未完了＝オンラインとはしません。
  クラッシュ後も現在まで時間を延ばさず、推定ライブ時間は提供しません。
- 最終観測は `players.last_seen_ms` です。更新ハートビートではなく、現在オンラインやサーバー生存の証明ではありません。
- 行動は `events.actor_kind='player'`、`event_kind='audit_block_change'` かつ
  `cause='player_destroy_attempt'`／`'player_place_attempt'` の**行数**です。amountや素材へ変換しません。
  基礎画面の旧4イベントソースに対応します。追加行動は上記の別source定義に従います。
  参加／退出も保存された `session_start`／`session_end` の行数です。
  キャンセル済み通知等が収集されない場合や、キュー拒否などの欠落は復元できません。
- ランキングはSQL集計した正の値のみ、値の降順→名前のバイナリ順→内部ID順。
  同値でも表示順位は安定した連番です。内部UUID/XUIDはAPIへ返さず、起動限りの不透明キーで選択します。
  1ページ最大100件、ページ0〜1000。UIはランキング20件、プレイヤー100件ずつです。
- 同接ピークは期間内の完結セッションから確認できる**下限**。同時刻の退出／参加を合算してから評価します。
  未完了セッションは含まれず、現在人数や真の全体ピークとは異なります。
- 無イベント・古い最終観測は無人／停止の証明ではありません。読取失敗時はエラーと前回値の可能性を表示します。

## 履歴：Phase 2の間隔方式（現在は上記の実処理方式を優先）

以下はbusy timer導入前の記録です。「未検証」「追加なし」は当時の候補についてで、
現在の実MSPT受け入れや新しい行動候補の状態は本ページ冒頭が正です。

26.60.0の固定コミット `072b9ffe0e9d9e0ec846f11d294880e892fe7770` の
[公式発火元](https://github.com/LiteLDev/LeviLamina/blob/072b9ffe0e9d9e0ec846f11d294880e892fe7770/src/ll/api/event/world/ServerLevelTickEvent.cpp)
を確認しました。`ServerLevel::_subTick` の **origin前**に発火する通知です。
dimensionのtick通知ではありません。処理終了を観測できないので、処理時間MSPTは計測できません。

新しい候補の `runtime.cpp` は同じLevelの通知間隔を `steady_clock` で計測します。
初回はウォームアップ。5秒以上の窓の **間隔数 × 1,000,000 / 経過µs** を上限20の
実効TPSとします。これはサーバーLevelコールバックの進行速度で、CPU処理時間ではありません。
別Levelの通知が混ざると、その有効化中は停止・無効化します。30秒超の窓は破棄し、
停止／一時中断から復帰した後は新しい窓を待ちます。tickスレッドはO(1)の時計／カウンター操作、
約5秒ごとのMCAPI人数取得とキュー投入のみ。SQLite書込みは既存の単一workerです。

保存形式は既存v4の `events` を使い、破壊的な移行はありません。
`event_kind=server_tick`, `actor_kind=system`, `cause=ll26.60.interval.v1` のみを対象に、
`amount` は間隔数、`session_id` は計測起動ID、`online_players` は窓末の観測人数、
`details_json` は `clock=steady`, `window_us`, `sampled_peak_online` です。
人数は公式MCAPI `Level::$getActivePlayerCount`。ピークは5秒ごとの観測最大値で、
途中で短時間だけ増えた人数は見逃す可能性があります。個々のプレイヤーのオンライン判定には転用しません。
**tick_mspt=0を維持し、旧server_tick_samplesには間隔データを入れません。**

新規に起動するcompanionはこの形式を読み、実測窓のTPS／人数／観測ピーク／更新時刻を表示します。
直近行が20秒超なら `stale`、不正／未来なら `invalid`、計測終了通知
`ll26.60.interval.end.v1` が最新なら `stopped`。いずれも現在TPS・人数をnullにし、
以前の正常行で埋めません。処理MSPTは常に未計測です。画面の集計期間にかかわらず、
サーバー計測欄は最新窓です。20秒内でも稼働保証ではなく、最後に永続化された観測値です。
キュー欠落・異常終了で終了通知が残らない場合も20秒後に古い値として扱います。

**現在稼働中のBDS二台と18767番のcompanionは更新・停止しません。**
稼働DLLは旧版のままなので、現行DBの実効TPSは依然未計測です。

## 読み取りとセキュリティ

DBはリポジトリ配下の既存ファイルのみ、SQLite URI `mode=ro` と `query_only` で開きます。
WALを無視する `immutable=1` は使いません。レスポンスごとにbackup APIで**メモリ内だけ**へ
一貫したコピーを作り、そのコピーで集計します。元DBのマイグレーション・journal変更・
checkpoint・INSERT／UPDATE／DELETEはありません。WAL読取の通常の共有ロックには参加します。
テスト用以外のDBファイルへ書き込む機能はありません。

稼働BDS配下の読取では既存WAL／SHMが揃うことを要求し、読取中は既存ファイルを保持します。
停止後にWAL／SHMが無くなった場合は、元フォルダに作成せずエラーにします。
サーバーを再起動したり、sidecarを手作業で消したりして直さないでください。
将来、閉じたDBを読みたい場合はユーザーが承認した別のプロジェクト内コピーを指定します。

読取上限は256 MiB、backupは2秒、集計VMは2秒の予算。HTTPは1接続ずつ、
ヘッダー合計8 KiB・全体2秒、keep-aliveなし。読み取りGETのみで管理・rollbackルートはありません。
HostとOriginをloopbackの同一originへ制限し、CORSを付与しません。
フレーム禁止、CSP、no-store、nosniff、no-referrerを設定します。
UIは `textContent`／DOM生成だけで名前を挿入し、HTMLとして解釈しません。
