# 採掘・設置v2と表示経路の整合（候補・実機未受入）

GameModeのtrue応答と同座標のブロック種類変化だけを数える限定観測です。
全採掘／全設置・アイテムドロップ量・ワールド保存・他Modを含む専属因果の証明ではありません。
稼働BDS・旧SQLite・18767には配備していません。受入済みMSPTは変更・再試験しません。

## 新しいネイティブソース

| 操作 | cause | 数量／種類 |
| --- | --- | --- |
| 採掘 | `ll26.60.gamemode_destroy_block.v2` | 同座標の型が変わった場合の入口ブロック型、1行＝1回 |
| 設置 | `ll26.60.gamemode_build_block.v2` | 同座標の非空気への型変化、処理後の型、1行＝1回 |

既存の公開GameModeフックを継続し、新しいフック・アドレス／offset推測はありません。
originは一度だけ呼び、bool／例外を変更しません。入口でBlockPos・Player弱参照・Level・
次元・型をコピー。完了後は弱参照を再解決して同じPlayerか確認し、未削除・同Level・
同次元の条件を満たす場合だけBlockSourceを読みます。再入れ子・失敗・無変化・不明は除外。
`same_player:true`／`same_level:true` と既存の限定scopeをv2詳細に保存します。

v2は実際に読んだBlockPosのXYZと次元をSQLiteの位置列へコピーします。旧v1の既定0座標を
実位置や原点と読み替えません。world_idは依然不明で、推測したworld名は保存しません。
範囲は既存の安全境界（-30000000＜X/Z＜30000000、-512≦Y≦512）。次元は既存の
Position.dimension型へ損失なく格納できる-1～127に限定し、128以上を折り返して記録しません。
これは全カスタム次元対応ではありません。

設置は渡された同じ座標だけを追跡します。クリック面の隣接座標・多重ブロックは追跡せず、
一般的な隣接設置が欠測する場合があります。sim_tick値を保存しますが、最終コミットを
保証する値とはしません。ゲームスレッドでDB処理せず、既存の有界single writerを使用します。

## 古い履歴と厳格な読取

v1の同じcauseを持つ履歴は削除せず、v1専用の既知9フィールド（設置11）を検査します。
v2は追加2フィールドを必須とします。v1行をv2のLevel／未削除確認の証拠へ昇格しません。
ブロック試行・空JSON・不明cause・個数2以上を「成功数」として合算しません。

ネイティブStatsReaderのmined個人・種類・順位・ページ総数・C APIと、Webの採掘／設置は、
型・amount=1・種類ID・before/after・hook/phase/scope・JSON bool／整数・再入フラグ等を照合。
設置ではJSONのhandと手の列も一致させます。重複キー・未知フィールド・不正JSON・
768 UTF-8バイト超・未来行を拒否し、未記録／不正行だけならnull、順位対象外とします。
SQLite値型も検査し、文字列や端数のamountを勝手に整数化しません。

ネイティブは読取専用接続に有界・決定的なJSON検査関数を登録し、固定SQLからだけ呼びます。
毎行の検査は有界ですが、ファイルI/OをOSレベルで中断する保証ではありません。
Webはこれまで通りJST日／月／全期間。native GUI／C APIは全期間であり、期間引数は追加していません。
GUIの説明とC APIのscope/source_contracts/final_world_commit_verified:falseへ限界を表示します。
これは独立C ABIで、LegacyRemoteCall互換を実装したという意味ではありません。

ここでの検査は保存済み証拠の契約を確認するもので、編集されたDBの真偽を認証する署名ではありません。
同じ座標の変化に他Modの作用が含まれる可能性、queue drop、呼ばれない経路は残ります。
古い不完全行はDBに残りますが、以前の緩いnative集計より値が小さく／未計測になる場合があります。
旧daily集計の書き換えはせず、対象表示はeventsの厳格な読取です。

## 検証と残りの受入

合成モデル→本番v2 builder→writer→SQLite→native個人／順位／C API→認証HTTP→実stats.jsの
合成DOMを照合します。旧v1、削除／Player/Level/次元交換、origin一回、座標、個数の型、
偽フラグ、重複JSON、未来行、欠測null、安定順位とページ情報、DBバイト非変更を検証します。
これは実ブラウザ・実BDS・実操作・ゲーム内GUIの受入ではありません。最終証跡は[STATUS](../STATUS.md)。

実機確認は承認済み通常ホスト経路の新root／未使用world・portsだけで行います。
survival採掘の種類・実座標、取消／再入・無変化、異次元、設置の同座標／隣接欠測を操作記録と
SQLite／GUI／APIで照合し、正常stop・閉DB integrityを確認する必要があります。
既存BDS／18767・認証・セキュリティ設定は変更せず、sandboxからオンラインBDSを再試行しません。
