# ネイティブ統計読取の限定レビュー（2026-11-07）

## 最新追補（以下の旧200種類窓／未対策項目を更新）

読取は全対象種類の合計／件数を計算し、保持する明細だけoffset/limitへ制限します。
旧200種類打ち切りは撤去。GUI12件、API100件以下。10万種類を超える場合は失敗。
SQLite busy待機50ms、VM進捗ハンドラの協調期限100msを設定し、RAIIで解除します。
OS／ディスクI/Oの強制中断やゲームスレッドのハードリアルタイム保証ではありません。
巨大な実worldでの負荷・操作試験はまだ必要です。

公開C宣言・エラーコード・buffer所有権をremote_api.hppへ追加し、全4関数をnoexcept
境界にしました。C++例外は-5へ変換、負の戻り値では古いJSONを消去します。
無効なポインターを受け取っても安全という保証ではなく、信頼するin-process呼出し用。
LegacyRemoteCallとのワイヤ互換・実他Mod検証・独立セキュリティレビューは未完了です。

新killed_by読取は厳密な型／JSON／種類／ID照合を共有し、原因コードを除外します。
詳細は[KILLED_BY_ATTRIBUTION.md](KILLED_BY_ATTRIBUTION.md)。他の全統計に同じ厳密さが
適用済みとは主張しません。既存pre_origin_amountを確認し、再導入されていた処理前
ダメージを確定CUSTOM damageへ昇格しないよう再修正。元観測は削除しません。

これは今回の変更範囲の自己点検であり、独立したセキュリティレビューや
LK全機能受け入れ・実クライアントGUI試験ではありません。

## 今回修正した箇所

- `/stats` が `summary.player_id` 自身を引数に渡す場合、result初期化より前にIDを
  所有コピーします。無効化されたstring_viewをSQLiteへ渡す問題を防ぎます。
- 名前はplayersから再取得。結果を初期化して表示名を失う問題を防ぎます。
- 完結・整合するセッションだけをUTC epochで読取。未終了・未来終了・負の開始・
  整合しないduration・非整数は除外。重複/入れ子/連続重複を統合し、隙間は数えません。
- 死亡後時間は最後の該当死亡時刻以後の**閉じたセッションの時間**だけ。
  オフライン実時間をプレイtickにせず、未終了を現在まで伸ばしません。
  50ms換算の下限で、実tickや現在onlineの証明ではありません。
- CUSTOM合計は提供せず、C APIではnull、GUIでは「異なる単位を合算しません」。
  時間ランキングと明細は同一SQL。無記録を収集済み0や全77実装済みに変換しません。
- 前処理の相互作用/攻撃回数/ダメージ通知を、確定CUSTOMのopen/eat/playや
  damage_taken/dealtへ昇格させません。元のdurableイベントは削除しません。
- 読取stepエラーを終端と混同せず失敗を返し、ranking limit/offsetを下層でも検査。
  人物・ページはバインド。SQLに埋め込む時計は内部int64の十進文字列だけです。
- 前後ページのcallbackはID・分類・ページを値で保持し、その時点のPlayer参照で
  再読取。古いPlayerポインターを非同期保持しません。失敗時は古い値を新結果として表示しません。
- GUI明細は現状200種類の窓、ランキング10件/頁・1000頁まで。キー選択77件を12件/頁。
  カタログ/翻訳は収集済み証明ではありません。

## 残る必須事項

全9分類・77キーの意味とソース、実プレイヤー→SQLite→GUI/APIの証拠は未完成です。
`killed_by`の原因コードと攻撃者エンティティ種類、craftの最終成立、耐久破損の成立、
移動の転送/次元/外力除外などを別に完成させる必要があります。
多くのキーは未対応/限定的です。読取時間値も上流の完全なtickカウンターと同等ではありません。

独自JSONバッファC ABIはLegacyRemoteCallのワイヤ互換・別Modからの実機呼出しを
まだ証明していません。プロセス内の信頼された呼出側向けで、ネットワークAPIの
認証代替ではありません。大量DBでのゲームスレッド読取の時間予算、明細200種類を
超えるページング、メモリ枯渇を含むC ABI例外境界も残課題です。

SQLite reader/単体テストはライブDBを変更せず、fixtureは新しいプロジェクト内の
専用一時領域だけを使います。既存BDS、world、18767、ネットワーク/認証/セキュリティ、
他プロジェクト、GitHubは変更しません。新DLLは通常ホストの新規隔離試験でのみ
受け入れ可能で、今回のコンパイルや既存の空smokeを実操作のPASSにしません。
